# CS2 Roulette — спецификация проекта

Этот документ — источник правды о приложении: зачем оно, как устроено, какие решения приняты
и почему, что отклонено, что в бэклоге. Обновляется при каждом значимом изменении.
Последнее обновление: 2026-10-26, версия приложения 0.10.1.

## 1. Назначение и пользователь

- Пользователь: русскоязычный стример CS2, Windows-ПК, OBS, мышь Logitech G PRO X Superlight 2
  (LIGHTSPEED-ресивер `046D:C54D`, провод `046D:C09B`), G HUB установлен. Не обязательно
  разработчик: запуск двойным кликом `run.bat`, панель на русском.
- Два стрим-ивента, работающие независимо и вместе:
  1. **Гонка вооружений** (Premier/любой режим): перед матчем приложение рандомит лоадаут по
     правилам CS2, стример вручную выставляет его в игре; в матче рулетка назначает оружие из
     этого лоадаута, килл назначенным оружием переводит к следующему; виджет в OBS показывает
     текущее + 2 следующих силуэтами на прозрачном фоне.
  2. **DPI-рулетка**: после каждой смерти (и по хоткею) колесо выбирает случайный DPI
     (по умолчанию 800–3200) и применяет его к мыши; виджет-колесо в OBS появляется только на
     время кручения, затем остаётся итоговое число до следующей смерти.
- Обычный DPI стримера — **3200**; он выделен отдельным цветом на колесе и подсвечивает число.

## 2. Ограничения и принципы

- Только Windows как целевая платформа; разработка ведётся на macOS (хоткеи и HID++ там не
  работают, есть имитация мыши `CS2R_DPI_BACKEND=fake`).
- Ничего не внедряется в процесс игры, игре не отправляется ввод (никакого SendInput, автобая).
  Хоткеи — `RegisterHotKey` (как у OBS/Discord), данные игры — официальный GSI. VAC-безопасно.
- Сервер слушает только `127.0.0.1`; запросы с чужих Origin/Host отклоняются (CSRF-защита),
  POST к `/api/*` требует `application/json`.
- Состояние серверное (server-authoritative): виджеты лишь рендерят снапшоты и переживают
  перезагрузку источника в OBS (в том числе доигрывают анимацию колеса).
- Приложение должно оставаться рабочим в любой момент: если мышь/hidapi недоступны — гонка
  вооружений работает как раньше; если лоадаут не сгенерирован — DPI-рулетка работает.

## 4. Правила CS2, на которые опирается код

- Лоадаут на сторону: 1 стартовый пистолет (T: Glock; CT: USP-S или P2000) + 4 пистолета из 6
  (P250, Dual Berettas, CZ75, Deagle, R8 + Tec-9/Five-SeveN) + 5 мид-тир из 11 (MP7, MP5-SD,
  UMP-45, P90, PP-Bizon, Nova, XM1014, M249, Negev + MAC-10/Sawed-Off или MP9/MAG-7) +
  5 винтовок из 6 (T: Galil, AK, SG553, SSG08, AWP, G3SG1) / 7 (CT: FAMAS, M4A4, M4A1-S, AUG,
  SSG08, AWP, SCAR-20). Взаимных исключений CS:GO нет. Проверено по патчноутам до 2026-10-22.
- GSI-имена: `weapon_m4a1` = M4A4, `weapon_m4a1_silencer` = M4A1-S, `weapon_hkp2000` = P2000,
  `weapon_revolver` = R8, `weapon_elite` = Dual Berettas, `weapon_galilar`, `weapon_sg556`,
  `weapon_cz75a`, `weapon_taser` = Zeus, ножи `weapon_knife*`/`weapon_bayonet` → `knife`.
- GSI (конфиг `game/csgo/cfg/gamestate_integration_cs2roulette.cfg`, читается при старте игры,
  без BOM): блоки provider, map, round, player_id, player_state, player_weapons,
  player_match_stats; buffer 0.0, throttle 0.0, heartbeat 10. Когда стример мёртв, блок
  `player` описывает наблюдаемого тиммейта — фильтр по `player.steamid == provider.steamid`.
- Блок GSI в панели: только «Установить конфиг» + статус; «Скачать конфиг», «Новый токен»,
  путь и токен спрятаны в «Дополнительно» (пользователь счёл их лишними).
- Статус GSI в панели: ник игрока в чипе шапки и блок «игрок / последний пакет / состояние» в
  разделе GSI; имя берётся и из пакетов с неверным токеном (`rejected_name`) с подсказкой
  «старый токен — перезапустите CS2». Конфиг читается игрой только при старте.
- Нет консольной команды для изменения слотов лоадаута и нет пресетов лоадаутов → автопроставка
  лоадаута в игре невозможна без симуляции кликов/подмены клиента (отклонено).

## 5. Гонка вооружений (поведение)

- Очередь: `queue[0]` — текущее, далее `visible_next` (по умолчанию 2) следующих; каждому слоту
  свой `uid` для анимации конвейера. Режимы пула: «мешок» (без повторов до исчерпания; новое
  заполнение исключает видимые) и «рандом» (без соседних повторов). В пул входят лоадаут стороны +
  опционально стартовый пистолет, нож, Zeus (раздельные тогглы `include_starting`,
  `include_knife`, `include_zeus`; старый ключ `include_extras` мигрируется в оба).
- Килл: рост `player.state.round_kills` в живом раунде (`map.phase == live`, не freezetime), в
  том же раунде или через смену номера раунда (поздний килл). Оружие — активное в предыдущем
  пакете (quick-switch учтён), fallback — текущее. `previously.round_kills` используется только
  если это не блок тиммейта (нет `steamid/name`). Гранаты: бросок HE/молотова помечает килл в
  окне 3 с / 9 с как «спорный» (в строгом режиме не считается, в режиме «любой» считается).
  Коллатерал (2 килла в одном пакете): второй не судится против следующего оружия.
- Автопереход: `strict` (только назначенным оружием, по умолчанию) / `any` / `off`;
  `kills_per_weapon` ≥ 1. Хоткей «Следующее» в течение 1,5 с после автоперехода игнорируется.
- Сторона: из GSI (`player.team`) переприменяется каждым пакетом; ручная кнопка T/CT; при смене
  стороны очередь перестраивается, текущее остаётся, если доступно новой стороне; счётчик киллов
  текущего сбрасывается, если оружие выбыло.
- `view_side` — какую сторону показывают вкладка панели и виджет лоадаута (меняется вкладкой,
  кнопками «Только T/CT» и автоматически при смене стороны).
- Клик по оружию в лоадауте открывает выбор (`openPicker` в panel.html → `POST /api/loadout/slot
  {side, category, old, new}` → `loadout.set_slot`, валидация стороны/категории/дублей) плюс
  пункт «случайное из оставшихся» (`/api/loadout/replace`). Пользователь может собрать свой
  лоадаут вручную.
- Пауза (`stop`) сохраняет всё, `start` возобновляет; «Сброс» — единственное разрушительное
  действие. Undo (20 шагов) восстанавливает очередь и счётчики; после смены стороны/лоадаута
  очередь пересобирается под актуальный пул.
- Хоткеи (F9 следующее, F8 перекрутить, F7 отмена, F6 крутить DPI) **выключены по умолчанию**
  с 0.8.3 по просьбе пользователя (ему хватает автоматики GSI); включаются на вкладке
  «Общее → Хоткеи», настройки свёрнуты. Подсказки клавиш на кнопках и чип в шапке показываются
  только при включённых хоткеях. Код и тесты сохранены.
- Виджет оружия: карточки шириной `120px × aspect` силуэта (aspect из viewBox SVG, 0.5–5.0,
  ширина 90–400px), следующие в масштабе 0.52, зазор 30px (между следующими 21px; по вертикали
  30 и 24); отступ окна 12px; счётчик под полоской (+10px, высота 34; по вертикали +22px).
  Раскладка горизонтальная/вертикальная, выравнивание, подписи (+42px), счётчик, бейдж x/y,
  подсветка цветом `overlay.match_color` когда в руках назначенное оружие (галочки нет).
  Фильтры (тени, вспышка) на обёртке `.iconwrap`. Карточки размещаются синхронно (без rAF).
- Виджет лоадаута: своя раскладка `overlay.loadout_layout` — `rows` (категория в строку:
  отступ 14, заголовок 44, колонка названия категории 150 + 14, ячейка 118×64 (46 без названий),
  зазор 12, высота строки 76/58) или `columns` (как в игре: три колонки 118 с зазором 14,
  заголовок колонки 20, ячейки с зазором 8); `overlay.loadout_names`. `?side=both` — обе стороны
  (строки — друг под другом, колонки — рядом, зазор 20).
- **Размеры источников OBS** считает панель (`weaponsBox`/`loadoutBox` в panel.html) по тем же
  константам; проверено измерением в браузере 2026-10-26. Значения по умолчанию: оружие
  горизонтально 891×188 (с подписями 891×230), вертикально 424×379 (465), лоадаут строки
  830×376 (обе 830×744), колонки 410×444 (обе 812×444), колесо DPI 600×750; всё × масштаб.

## 6. DPI-рулетка (поведение)

- Значения колеса = база ∪ зрительские. База: диапазон `min_dpi..max_dpi/step` (отключаемый
  `use_range`) ∪ `custom_values` (ручной список, снэп к сетке, ≤60). Сетка читается с мыши
  (0x2202 fn2), fallback — известная (шаг 1/2/5/10/20/50/100/125/200 до 44000).
  `pool_mode=bag` (по умолчанию): выпавшее базовое значение попадает в `consumed` и уходит с
  колеса, пока база не исчерпана (тогда `consumed` очищается); «Новый круг» очищает вручную.
  Зрительские значения (`viewer_values`: value, user, t, source) одноразовые: исчезают, когда
  выпали. Пустое колесо → `[home_dpi]`. Не выпадать на текущее (опция).
- Зрители: `viewer_enabled` → анонимный IRC-читатель чата `chat.channel_login` (логин
  подставляется из профиля SE при «Проверить токен»). Сообщение с тегом `custom-reward-id`
  (текст награды за баллы канала) → число валидируется (`viewer_min..viewer_max`, лимиты
  `viewer_max_values`, `viewer_per_user`) и добавляется; `viewer_reward_id` запоминается в
  режиме «Определить» (`learn_reward`) по первому выкупу, иначе принимаются любые награды с
  числом. Опциональная чат-команда `viewer_command` (например `!dpi 1600`). Подтверждение в
  чат через SE (`viewer_announce`, шаблон `chat.viewer_template`). Тестовые эндпоинты
  `/api/twitch/chat`, `/api/dpi/viewer/add`.
- Триггеры: смерть из GSI (здоровье → 0 своего игрока или переключение блока `player` на
  тиммейта в живом раунде; в разминке не считается; одна смерть — одно событие до следующего
  «жив»), хоткей F6, кнопка в панели. Кулдаун после кручения (по умолчанию 8 с).
- Применение: сервер выбирает значение и параметры анимации (`index`, `offset`, `revolutions`,
  `duration_ms`, `started_at`), публикует `dpi_spin`; DPI применяется в момент остановки колеса
  (`apply_at=stop`, по умолчанию) или сразу. `target_dpi` выставляется только при применении,
  сторож не трогает мышь пока есть отложенное применение.
- Мышь: HID++ 2.0 напрямую через hidapi (работает рядом с G HUB; vendor-коллекции usage page
  0xFF00, usage 1 короткие / 2 длинные отчёты). Требует host-режима (0x8100 fn1 = 2; в
  onboard-режиме запись отвергается ошибкой 0x05; мыши без 0x8100 ничего не требуют).
  Поддерживаются обе фичи DPI: 0x2202 (HERO 2: Superlight 2, G502 X…) и 0x2201 (G304/G305,
  G Pro Wireless, G403…: fn1 список с 1 эхо-байтом, fn2 get `[sensor, dpi, default]`, fn3 set
  `[sensor, dpi]`, без LOD). Выбор автоматический (`HidppDevice.dpi_feature`). Баг 0.6.1:
  сообщение об ошибке подключения само падало (`format 'x'` на строке) — исправлено. Запись: 0x2202 fn6 `[sensor, dpiX, dpiY, lod]`,
  LOD берётся из fn5 (чтение `[sensor, dpiX, defX, dpiY, defY, lod]`). Диапазоны: fn2 с
  параметрами **`[sensor, direction, page]`**, ответ — непрерывный поток 13 байт на страницу,
  слово с тремя старшими битами = шаг (`& 0x1FFF`), терминатор 0 (как в Solaar
  `produce_dpi_list`). Ошибка порядка параметров давала колесо 100–500 (исправлено в 0.3.1).
- Сторож (`guard`): каждые 3 с читает DPI, при расхождении с целевым переприменяет (G HUB может
  вернуть DPI профиля при alt-tab/пробуждении); рекомендуется Persistent Profile в G HUB.
- «Вернуть мой DPI» применяет `home_dpi` (3200). Диагностика: «Проверить мышь» (имя, протокол,
  режим, DPI, LOD, размер сетки), «Host-режим».
- Виджет: `wheel_mode = spin` (колесо видно только во время кручения + `wheel_linger_s` после
  остановки, число остаётся до следующей смерти) или `always`; `idle_hide_s` прячет и число;
  сегмент `home_dpi` в цвете `home_color`, число при выпадении на него — тем же цветом, без
  текстовых подписей вроде «твой обычный» (пользователь просил убрать).

## 6a. Чат Twitch (StreamElements)

- Провайдер: StreamElements (выбран как самый простой: нужен только JWT-токен канала из
  дашборда, без регистрации приложения). `POST https://api.streamelements.com/kappa/v2/bot/
  {channelId}/say {"message"}` с `Authorization: Bearer <JWT>`; channelId — claim `channel` из
  payload JWT (без верификации), проверка/имя канала — `GET /kappa/v2/channels/me`.
- Состояние бота: `GET /bot/{channelId}` → `{"bot": {enabled, name, joined, muted, mod}}`;
  `POST /bot/{channelId}/join` (400 «already in your channel» = ок). `verify()` читает состояние
  и сам подключает бота, если `joined=false`; `bot_problem()` объясняет, почему сообщений не
  видно (не в канале / muted / выключен); панель показывает это в строке статуса и кнопку
  «Подключить бота к каналу» (`POST /api/chat/join`). Важно: `/say` отвечает 200 даже когда
  сообщение не появляется (бот не в канале, muted, либо Twitch прячет бота после долгого простоя
  чата — лечится парой ручных сообщений). Источник: неофициальная OpenAPI-спека
  c4ldas/streamelements-api (`channel_sayrequest` = `{message}`). Ответ `/say`
  (`{status, channel, message}`) хранится как `last_response`; отправки и ошибки пишутся в app.log.
- Настройки `chat`: enabled, se_jwt (секрет; в API/SSE только `se_jwt_set`), on_start,
  on_weapon, on_dpi, шаблоны (`{weapon} {completed} {kills} {side} {dpi} {reason}`),
  min_interval_s (≥0.5, по умолчанию 2). Токен лежит в data/settings.json.
- Триггеры: смена текущего оружия при запущенной сессии (старт/возобновление с нуля → шаблон
  старта; иначе шаблон оружия; детект по `(running, current_uid)` в `_on_roulette_change`),
  успешное применение DPI (`DpiService.on_applied`, любая причина). Отправка из рабочего потока;
  всплески одного типа схлопываются в последнее сообщение.
- Панель: вкладка «Общее → Чат Twitch через StreamElements»: сохранить/удалить токен,
  «Проверить токен», «Отправить тест», тогглы, шаблоны, лог отправок.
- Отказы зрителям (`on_reject`, `reject_template` «❌ {user}: {reason}»): отправляются при
  непринятом значении, не чаще `reject_cooldown_s` (30 с) на зрителя; ключ очереди
  `reject:<user>`, поэтому разные зрители не схлопываются. Подтверждения — `viewer_template`.
- Nightbot (нужна OAuth-регистрация приложения) и Moobot (нет API) отклонены как более сложные.
- Награды за баллы канала читаются из чата анонимно (IRC `justinfan`, тег `custom-reward-id`)
  вместо EventSub, чтобы не регистрировать приложение Twitch; риск: Twitch может ограничить
  анонимный IRC в будущем — тогда переход на EventSub WebSocket с Device Code Grant.

## 7. API и события

HTTP (все POST — JSON): `/api/state`, `/api/weapons`, `/api/loadout/generate {sides}`,
`/api/loadout/replace {side,category,weapon}`, `/api/loadout/view {side}`, `/api/loadout/text`,
`/api/session/start|stop|reset`, `/api/roulette/next|reroll|undo|kill`, `/api/side {side}`,
`/api/settings` (GET/POST; секции roulette/overlay/hotkeys/dpi, `regenerate_token`, `port`;
ответ содержит `rejected`), `/gsi` (всегда 2xx), `/api/gsi/cfg|info|install`, `/api/hotkeys`,
`/api/dpi/status|spin|apply|home|probe|hostmode|death`, `/api/dpi/values/add|remove`,
`/api/dpi/cycle/reset`, `/api/dpi/viewer/add|remove|clear`, `/api/dpi/reward/learn`,
`/api/chat/verify|test`, `/api/twitch/chat` (симуляция), `/api/docs` (справка из QUICKSTART.md:
`{html, headings}`). Страницы:
`/`, `/overlay/weapons`, `/overlay/loadout`, `/overlay/dpi`.

SSE `/events`: `snapshot` (полный), `roulette`, `gsi`, `settings`, `hotkeys`, `kill`
(`finished_uid` для вспышки на нужной карточке), `hotkey`, `dpi`, `dpi_spin`, `chat`, `twitch`,
`clients`. Брокер помнит метаданные подписчиков: страница из Referer (`weapons|loadout|dpi|
panel`) и признак OBS (user agent obs-browser содержит `OBS/x.y.z`); снапшот отдаёт
`clients: {page: {obs, browser}}`, чек-лист по ним показывает «виджет подключён из OBS».

Параметры URL виджетов перекрывают настройки: оружие — `scale, layout, align, labels, counter,
kills, match, color, accent, matchcolor, bg, debug, x/y`; лоадаут — `side (auto|T|CT|both),
scale, names, color, accent, bg`; DPI — `scale, labels, wheel (spin|always), linger, hide,
current, home, homecolor, color, accent, bg, debug`.

## 8. Панель (UI)

Пять вкладок (запоминаются в localStorage/hash, `hashchange` переключает): **Startup** (живой чек-лист: CS2/GSI,
лоадаут, виджеты в OBS, мышь, колесо; «по желанию»: лоадаут-виджет, чат SE, награды,
автозапуск; при первом запуске открывается сама, пока обязательные пункты не зелёные;
пользователь просил назвать именно «Startup», без лозунгов), **Оружие** (очередь, кнопки, статистика, лог,
лоадаут с вкладкой T/CT, настройки гонки, настройки виджета оружия), **DPI** (текущий DPI,
кнопки, диагностика мыши, лог, настройки DPI, настройки виджета), **Общее** (GSI, хоткеи,
разное, **все цвета в одном блоке**, ссылки на виджеты), **Справка** (QUICKSTART.md, отрендеренный
`app/docs.py`; слева оглавление по h2 с подсветкой текущего раздела — в последнем экране страницы
опорная линия съезжает вниз, чтобы последние разделы тоже подсвечивались; клик по пункту закрепляет
его до ручной прокрутки). В блоках панели **нет поясняющих текстов** (пользователь: «много лишних
комментов»): остались только динамические статусы и строка размера источника; всё объясняющее — во
вкладке «Справка». Кнопки действий сгруппированы в блоки с подписями в две колонки (`.controls > .bg`): гонка —
«Сессия» (Старт/Продолжить, Пауза, Сброс) и «Оружие» (Следующее, Перекрутить; кнопка «Отмена»
убрана по просьбе, API undo остался); DPI — «Колесо» (Крутить, Вернуть мой DPI), «Мышь»
(Проверить, Host-режим), «Поставить DPI вручную». Поля — единый стиль
(высота 36px, тогглы-переключатели); все `<select data-key>` заменяются собственным выпадающим
списком (`enhanceSelects` в panel.html: скрытый нативный select хранит значение и шлёт change,
рядом рисуется `.dd` с кнопкой и меню), потому что нативные списки в Windows нельзя затемнить.
Поле JWT — `.tokenbox` (моноширинный ввод, кнопка показать/скрыть, «Сохранить», «Удалить»). Настройки сохраняются при
изменении поля (`data-key="группа.ключ"` → `POST /api/settings`).

## 9. Принятые и отклонённые решения

- Прямой HID++ выбран вместо WebSocket G HUB (`ws://localhost:9010`: SET-пути DPI не
  подтверждены ни одним публичным проектом) и Lua (`SetMouseDPITable` не реализован в G HUB).
  Подтверждено на мыши пользователя 2026-10-25: мышь находится, колесо крутит и применяет.
- Автопроставка лоадаута в игре — невозможна легально; отклонено.
- Авто-cfg с `buy <оружие>` под бинд — реализовано и **откачено по просьбе пользователя**
  («такое мне не подходит»). Не предлагать снова.
- Подпись «твой обычный» у числа DPI — убрана по просьбе.
- Галочка «в руках» заменена подсветкой цветом по просьбе.
- Режим колеса по умолчанию — только во время кручения (просьба пользователя).
- build.bat проверяет `import hid` до сборки и наличие `_internal\hid*.pyd` после: пользователи
  exe жаловались на «требует зависимости» — это сообщение DPI-модуля об отсутствующем hidapi в
  сборке; в frozen-режиме сообщение теперь содержит текст ошибки импорта и совет пересобрать.
- Поясняющие подсказки в блоках панели убраны (v0.10.0), документация — вкладка «Справка» из
  QUICKSTART.md. Не возвращать длинные hint-тексты в блоки; новое объяснение — в QUICKSTART.md.

## 10. Бэклог и открытые вопросы

- ~~Twitch-бот~~ — сделано через StreamElements в 0.5.0 (см. 6a). Исходный анализ: документация JeetBot (docs.jeetbot.cc,
  прочитана 2026-10-26) даёт только переменную `$(api URL $.path)` в кастомных командах:
  GET по фиксированному **публичному HTTPS** URL, кэш 15 с, кулдаун 5 с, до 3 команд с API на
  бесплатном тарифе; никакого push-API/webhook/интеграций нет. Значит: (1) автоматические
  сообщения «новое оружие/DPI» возможны только если шлёт само приложение — Twitch Helix «Send
  Chat Message» с Device Code Grant (пользователь заводит приложение на dev.twitch.tv ради
  Client ID; токены с refresh); альтернативы StreamElements `/kappa/v2/bot/{channel}/say` (JWT)
  или Streamer.bot (локальный WebSocket); (2) команды зрителей `!dpi` / `!оружие` через JeetBot
  возможны, если состояние опубликовать по публичному HTTPS JSON (туннель вроде Cloudflare
  Tunnel или облачный JSON-бин, куда приложение пишет состояние). Решение за пользователем.
- Проверить на ПК пользователя: предупреждение UIPI, поведение G HUB при alt-tab (нужен ли
  Persistent Profile), реальные значения `map.mode` в Premier.
- Возможные улучшения: пул «обе стороны» для Deathmatch; экспорт статистики сессии; звук при
  килле/кручении; PyInstaller-сборка без Python.

## 9a. Запуск, трей, сборка

- Обычный запуск — трей (`run.bat` → `pythonw start_tray.pyw`); uvicorn работает в фоновом
  потоке (`uvicorn.Server`, `capture_signals` вне главного потока ничего не делает), иконка
  pystray держит главный поток. `print()` в windowed-режиме безопасен (stdout None).
- `--console` возвращает консоль и StreamHandler; frozen exe по умолчанию трей.
- Автозапуск: переключатель в трее и в панели («Общее → Разное», `POST /api/autostart`).
- Сборка только на Windows (`build.bat`); на macOS кросс-сборка невозможна. SmartScreen без
  подписи предупреждает один раз. `--onedir` ради антивирусов.

## 10a. Производительность (замер 2026-10-26, macOS, фоновый режим)

Сервер в простое: ~0.1 % CPU, 19 МБ RSS, 12 потоков (uvicorn, хоткеи, DPI-сторож, чат SE,
IRC-читатель, пул потоков). Что делается в фоне: сторож DPI читает мышь раз в 3 с (с
экспоненциальным откатом до 60 с, если мышь не отвечает), housekeeping GSI раз в 5 с,
SSE-пинг раз в 15 с на клиента, IRC-сокет блокирующий (0 % без сообщений). Поиск папки CS2
(реестр + vdf) кэшируется на 30 с. Снапшоты публикуются только по событиям; `gsi`-события
троттлятся (изменение ключевых полей или 2 с). Виджеты: rAF только во время кручения колеса,
карточки оружия — CSS-переходы.
